# Social platform API capability and access matrix

This is a feasibility snapshot, not an integration commitment. Platform policies, permissions, quotas, and app-review processes change; re-check the linked official documentation and test an approved developer app before scheduling delivery work.

## Platform comparison

| Platform | Official publishing capability | Account / permission requirements | Approval, quota, or cost gate | Phase 1 status |
|---|---|---|---|---|
| Instagram | Official publishing endpoints support media containers and publishing for professional accounts. The current platform overview recommends Unified Login for new integrations; publishing requires the appropriate Instagram permissions. | Professional Business or Creator account; depending on login type, Business Login for Instagram or Facebook Login for Business, and associated `instagram_*` or `instagram_business_*` permissions. A Facebook Page is required only for the Facebook Login setup, not the other two. | Standard Access is intended for accounts the app owns/manages or app-role users. Serving unrelated customers requires Advanced Access; Meta says Advanced Access requires business verification and may require App Review. Instagram documents a 100 API-published-posts-per-account moving 24-hour limit. Publicly accessible media and Page Publishing Authorization may also be prerequisites. | Not implemented; verify app-review approval and media workflows before committing. |
| Facebook Pages | Pages API supports text/link and media publishing, including scheduled Page posts. | Facebook Login, Page access token, Page tasks such as `CREATE_CONTENT`, `MANAGE`, and `MODERATE`; permissions include `pages_manage_posts` and `pages_read_engagement`, with additional permissions depending on actions/media. | Standard Access is restricted to app-role users. Advanced Access is required to serve users without app roles and requires business verification; individual permissions/features may require App Review. Scheduled posts must be between 10 minutes and 30 days in the future per the current guide. | Not implemented; likely candidate for a first proof of concept after Meta approvals. |
| TikTok | TikTok publishes an official Content Posting API, but its official documentation endpoints returned HTTP 503 during this review, so current direct-post/upload behavior and restrictions were not independently confirmed here. | Exact current scopes, supported account/content types, and access steps must be verified from TikTok's current developer documentation and app dashboard. | Do not assume public posting, audit status, or pricing. Validate API access, app review/audit requirements, and account eligibility with an approved test app. | Explicitly unverified; do not promise publishing until checked directly with TikTok. |
| YouTube | YouTube Data API `videos.insert` uploads videos and can set metadata and publish timing/status. | OAuth authorization with an upload-capable scope such as `youtube.upload`; channel-owner consent is required. | The current default quota includes 100 `videos.insert` calls per day (a separate quota bucket); other API calls use a shared daily quota. Review the current quota and project verification rules before production. | Not implemented; quota and OAuth verification need a prototype. |
| LinkedIn | Posts API creates organic and sponsored posts, including text, image, video, document, and selected multi-image formats. | `w_member_social` for member posting; `w_organization_social` for organization posting, plus required organization page roles. Requests need version headers. | Some read permissions are restricted to approved users; access to member/org posting products must be confirmed for the app. Organization posting is limited by the member's page role. | Not implemented; developer product access needs confirmation. |
| X | X API supports creating posts and other interactions. | OAuth and the endpoint's currently supported user/app authorization; verify create-post scopes in the API reference when implementing. | Current API is pay-per-use. The published price snapshot listed $0.015 per create-post request and $0.200 for a post with a URL; rates can change and should be checked in the developer console. | Not implemented; API is not a zero-cost MVP assumption. |
| Pinterest | An official Pinterest API v5 Pin-creation reference exists, but its page is rendered client-side and did not expose the current operation details in this review. | Confirm current app access, OAuth scopes, board/account requirements, and supported media using the live reference and developer console. | Verify approval, endpoint-level limits, and cost/access terms before building. | Explicitly unverified; do not promise publishing until checked directly with Pinterest. |

## Recommendation

Treat publishing as a per-platform integration with its own OAuth connection, token lifecycle, permissions, media preparation, approval workflow, quota budget, webhook/reconciliation behavior, and error mapping. Start with one platform only after the developer app receives the needed access. Do not model a "publish to all networks" operation as successful unless every selected network returns a confirmed provider post ID.
