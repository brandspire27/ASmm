# Phase 2B — Facebook Login for Business connection pilot
Apply over Phase 4A. No SQL migration, dependency updates or paid services required. This patch is for the General **User access token** configuration, not Unified Login/SUAT. In Meta confirm the configuration token type and the six content permissions: pages_show_list, pages_read_engagement, pages_manage_posts, instagram_basic, instagram_content_publish, business_management (per the Facebook Login Instagram setup). Keep ads permissions out of this configuration. App must remain unpublished/development mode for this pilot; test only as an eligible app-role user managing a Facebook Page with a linked Instagram professional account. Meta may require additional access/verification for client accounts.

Back up your project. Merge files; do not replace .env.local or lockfiles. Add `META_LOGIN_CONFIG_ID=YOUR_CONFIGURATION_ID` to existing .env.local. Keep existing App ID, App Secret, encryption key, service role key, version and SOCIAL_APP_URL. For localhost use `http://localhost:3000` and callback `/api/social/meta/callback`; the Meta settings screen says localhost redirects are automatically allowed in development mode. Do not use 127.0.0.1 or a different port with this configuration. Restart the dev server. No credentials should be shared or committed.

Run `node --test verification/test_meta_oauth.cjs`, `npx tsc --noEmit`, `npm run lint`, `npm run build`. Start `npm run dev`. Sign in as workspace owner/admin, select a Focus Client, open http://localhost:3000/social-accounts, Connect with Meta. Approve only the intended test assets, then explicitly save each account. Finish selection clears pending discovery data. Refresh, inspect reported user grants. Reconnect to upgrade existing grants. If Meta reports an error, share the sanitized terminal line (endpoint, numeric HTTP/API codes only) and error screen without URLs containing OAuth codes, tokens or secrets. Do not publish the app or activate ads yet.

Limitations: this uses legacy Instagram API with Facebook Login and retains the existing short-to-long user token exchange, /me/permissions and /me/accounts discovery. Meta Unified Login/SUAT uses another flow; this patch does not implement it. The actual configured user-token flow, Meta grants and discovery require live verification. The reported user grants do not prove each Page/Instagram asset has granted the required tasks, granular access or valid Page token. Publishing stays disabled. No queue jobs are activated. Next stage requires account-specific token/asset capability checks and an authorized test publish. No database changes. Existing Phase 4A remains intact.
