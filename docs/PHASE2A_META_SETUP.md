# Phase 2A: Meta connection pilot

This is a read-authorization pilot, NOT a publisher. It uses Meta Graph API with Facebook Login, discovers managed Pages and their linked Instagram professional accounts, and permits explicit per-client selection. It does not connect personal profiles, standalone Instagram Login accounts, or fetch analytics. Page-token validity and live account capabilities are not continuously checked. Publishing and permission upgrades are future work.

1. Back up your existing project and Supabase database. Copy patch contents into the project root; no dependency or environment files are overwritten. Apply only `supabase/migrations/20261126100000_phase2a_meta_connections.sql`, then run `verification/check_phase2a.sql`; all eight columns should be true. The migration requires Phase 1A.2 and earlier migrations.
2. Create a Meta developer app with an appropriate Facebook Login / Facebook Login for Business use case supporting Pages and Instagram API with Facebook Login. Use development/test mode and an authorized app-role user. Link an Instagram Business or Creator account to a Facebook Page you manage. Request `pages_show_list`, `pages_read_engagement`, and `instagram_basic` as appropriate; do not request publish scopes yet. If your chosen Meta app configuration requires a Login for Business configuration ID or different OAuth setup, this pilot needs adaptation before live OAuth. App review/advanced access and applicable verification are needed for external clients. See https://developers.facebook.com/docs/graph-api/ and https://www.postman.com/meta/instagram/ .
3. Configure the exact valid OAuth redirect URI: `http://localhost:3000/api/social/meta/callback` if allowed for your development app, otherwise an approved HTTPS deployment origin and the identical path. Set `SOCIAL_APP_URL` to that origin, without a path. Browser origin must match. Meta settings and actual authorization are not verified in this package.
4. Append the missing variables from `docs/PHASE2A_META_ENV.txt` to `.env.local`. Use the same Supabase project as the existing public URL/key. Get the server-only service_role key from the Supabase project API Keys settings (legacy service_role key if needed). Never expose it to the browser or prefix it NEXT_PUBLIC_. Get App ID and App Secret from your Meta app. Generate a new 32-byte random key using PowerShell: `node -e "console.log(require('node:crypto').randomBytes(32).toString('hex'))"`. Paste the 64 hexadecimal characters into SOCIAL_TOKEN_ENCRYPTION_KEY. Back up this key securely; changing it makes old encrypted tokens unreadable. Never send it in chat or commit it. Do not duplicate existing variables. Restart the dev server after updating env.
5. Run `npm audit`, `npx tsc --noEmit`, `npm run lint`, `npm run build`. The patch adds no npm dependencies. Run `npm run dev`. Sign in as a workspace owner/admin, choose a Focus Client, open Social Accounts, and click Connect with Meta. Authorize only test assets. On return, choose a Page and/or its linked professional Instagram account, save them individually, then click Finish selection to clear temporary discovery data. Confirm saved accounts persist after refresh. Disconnect locally and confirm removal; use Meta settings to revoke app access separately if needed.
6. Test with a second client in the same workspace and a different organization, and with a non-admin role. No other client's account list may be visible and forged workspace/client API requests must return 403. Direct anon/authenticated requests to both tables must fail. Test OAuth cancellation, expired/incorrect state, callback replay, missing env and unauthorized client ID. Do not deploy to customers until these pass.

Security: random hashed single-use OAuth state with authenticated user/workspace/client binding, 10-minute expiry, server-side permission check on each operation, authenticated AES-256-GCM encryption with account-specific AAD, explicit account selection, and local-only disconnect. Pending discovery credentials are encrypted and inaccessible after expiry, cleared by Finish or on next start/list for that user; a production periodic deletion job, stronger atomic distributed rate limits, key rotation and ongoing token health/revocation handling are still required. No token, app secret, or service key is returned to browser. No fake publishing status. The chosen server service role bypasses RLS, so every endpoint explicitly authorizes and scopes operations; independent adversarial tests remain mandatory. Meta access depends on developer configuration and permissions. Large Page lists above the bounded pagination limit are rejected rather than silently truncated. No external API calls were executed by the patch author.
